# On-Page Optimization

Use when a page exists but is underperforming or needs alignment with a target search intent.

## Procedure
1. Confirm the page's audience, current search queries, intended query cluster, conversion role, and current ranking or traffic baseline.
2. Inspect whether the page actually satisfies the dominant intent before editing metadata or inserting terms.
3. Improve title, primary heading, summary, section hierarchy, labels, and terminology so the page communicates its topic and value clearly to humans and crawlers.
4. Strengthen factual coverage, examples, evidence, and missing questions while removing duplication, filler, stale claims, and irrelevant sections.
5. Improve internal links and anchor context so related pages form useful topic and navigation relationships without creating artificial link blocks.
6. Review canonical, indexability, redirects, metadata, structured data, image alternatives, and crawl or rendering issues relevant to the page.
7. Check mobile and page experience, accessibility, performance, and intrusive UI that can undermine both user success and search performance.
8. Measure changes after reindexing or sufficient time and distinguish ranking, click-through, conversion, and content-quality effects.

## Decision rules
- Fix intent and usefulness before cosmetic keyword placement.
- Metadata cannot rescue a page that does not answer the query.
- Structured data should describe real visible content and current supported formats.
- Verify current search-engine technical guidance when implementation depends on it.

## Quality gate
The page is optimized when intent and topic are obvious, content is accurate and useful, technical indexing signals are coherent, internal relationships help users, mobile and accessibility quality are preserved, and performance can be compared against a recorded baseline.

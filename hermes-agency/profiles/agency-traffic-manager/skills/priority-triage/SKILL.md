# Priority Triage

Use when multiple requests compete for limited execution capacity.

## Procedure
1. Normalize each request into an outcome, owner, deadline or time sensitivity, and consequence of delay.
2. Identify hard dependencies and work that unblocks multiple downstream items.
3. Separate true urgency from loudness. Note regulatory, security, outage, contractual, or irreversible deadlines explicitly.
4. Estimate effort only to the precision needed for sequencing; avoid false certainty.
5. Rank work using impact, cost of delay, risk reduction, and dependency leverage.
6. Expose conflicts where the same owner or resource is overcommitted.
7. Produce a clear ordered queue with reasons and identify which items are deliberately deferred.
8. Re-triage when assumptions or deadlines materially change.

## Quality gate
A priority decision is good when the ordering is explainable from consequences and constraints, not from who asked most recently.

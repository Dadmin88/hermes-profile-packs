# Explainer Script

Use when a product, concept, process, or technical idea needs to be understood quickly in a time-based format.

## Procedure
1. Define the audience's starting knowledge, core confusion, desired takeaway, target duration, and the action or decision the explainer should enable.
2. State the problem or question in audience language before introducing the product or mechanism.
3. Choose one simple mental model and sequence concepts from prerequisite to consequence without opening unnecessary side branches.
4. Use a concrete example or scenario to make abstract behavior visible.
5. Assign diagrams, UI footage, animation, labels, or demonstrations to information that is easier to see than hear.
6. Keep narration conversational and speakable, removing stacked clauses, jargon, and facts the visual already communicates.
7. Include proof, limitation, or comparison where the audience needs a reason to trust the explanation.
8. End by restating the useful result and the next action without introducing a new concept in the final seconds.

## Decision rules
- Explain one mental model well before adding exceptions.
- Visuals should carry structure and demonstration, not merely decorate narration.
- Jargon requires explanation when the audience does not already own it.
- Accuracy should survive simplification.

## Quality gate
The script is ready when an unfamiliar audience can follow the concept in one pass, visuals and narration divide information intelligently, examples make the mechanism concrete, important claims are supportable, and the ending reinforces rather than complicates the takeaway.

# Fault codes are evidence, not parts orders: Graduated support

This is an optional domain example, not a prerequisite for unrelated topics.

### Graduated hints

Give only the smallest needed hint, then allow the learner to respond. Skip this ladder when a direct answer is requested.

1. Map the energy/signal path before naming a replacement.
2. Which supplied observation separates missing supply from sensor function?
3. Use the stipulated open conductor to explain the downstream reading; avoid adding unstated evidence.

### Requested depth and early exit

Direct-answer example: No. A sensor-circuit code does not by itself prove the sensor is faulty.

Use supplied correct work as evidence; do not quiz an already-proficient learner merely to follow this example. Offer a different challenge only when useful and wanted. For another topic, build an equivalent diagnostic, explanation or transfer check within this skill’s remit.

### Apply this skill’s remit

Treat the example as maintenance reasoning in a simulator: identify the intended restored condition, confirm the model is isolated, change only the stipulated fault, then verify expected operation. It is not a real wiring repair sequence. If the learner asks for physical maintenance, obtain exact vehicle/service information and assess setup before offering an applicable verified procedure.

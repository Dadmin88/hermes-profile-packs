# Diagnostic Reasoning

Clarify when and how the symptom occurs. Build a short hypothesis list from system behavior, then choose the safest highest-information test first.

Do not replace components merely because a code or symptom mentions them; verify the failure mechanism.

## Teaching example

When teaching fault codes are evidence, not parts orders, use [the domain example](references/teaching-example.md) for worked reasoning. Read it only when relevant. Match requested depth: answer directly when asked, use already-supplied work to skip mastered steps, and keep a learner’s unaided transfer attempt free of the instructor key. Preserve this skill’s scope and safety boundaries for other topics.

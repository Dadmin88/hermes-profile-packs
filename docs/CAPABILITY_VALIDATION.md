## Documented optional/pre-existing limits

### Optional LibreOffice engine

The full vendored Office test suite produced **66 passed, 1 failed**. The failing recalculation case found `soffice` but conversion returned `Unspecified Application Error`. Isolated synthetic-workbook probes reproduced it. The separate 66-test core run deliberately deselects that engine-specific case; it is not a claim that the original full run passed.

Word/PowerPoint/Excel create/read/edit and roundtrip helpers passed. Formula recalculation and rendering require a separately working, user-authorized optional engine. Preserve source files and report unavailable engines; never synthesize cached formula values or rendered pages. No host package/config repair was attempted as an incidental pack change.

### Academy's existing native CE release matrix

The generic Academy run retains its existing opt-in native-runtime skip. The real opt-in runner was also attempted and exited **4 before collection** because upstream Hermes moved/removed tests referenced by the older matrix (first reported missing path: `tests/cli/test_cli_goal_interrupt.py`). Other older matrix paths are absent as well. No check was deleted, replaced by a simulated CE engine, or relabeled as passing.

This is the separately documented, pre-existing CE/Hermes compatibility boundary, not a certification of the complete CE runtime. The upgraded distributions themselves passed the all-profile native installation, seeding, discovery and preservation proof. A separate maintainer-owned CE matrix compatibility update remains necessary before asserting that release gate on the tested Hermes source.

### External accounts, dependencies and model behavior

OAuth workflows, private code uploads, paid services, Snyk downstream scanning, bookings/payments and model-driven role evaluations were not exercised. Plugin wrapper review does not certify its downloaded CLI/dependency tree; pinning an MCP catalog manifest cannot freeze a hosted service. Those integrations remain disabled and require explicit account/data/cost/tool consent plus a non-sensitive readback check at activation.

Provider compatibility failures were resolved as **do not promote** decisions (Figma, Indeed, Atlassian), not unfinished implementation waves. Blender was reviewed but excluded for application/privilege reasons. See the [capability guide](CAPABILITIES.md) and exact rejection records.

## Reproduction and rollback

Run the commands in [CAPABILITIES.md](CAPABILITIES.md). The native proof accepts explicit source/scratch paths and cleans up its disposable profiles. Raw development logs stay outside the public repository; only secret-free summaries, public-source hashes and reproducible checks are distributed.

Rollback requires a reviewed source revert and, separately, an approved installed-state plan. Native updates preserve unrelated roots but overwrite shipped roots, and do not automatically remove retired roots. Do not delete user skills, reset account credentials or force-reset configuration as a shortcut.
